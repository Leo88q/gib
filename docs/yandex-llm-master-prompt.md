# Мастер-промпт для Яндекс AI Studio + команда вызова

**Статус: написано, но НЕ запускалось.** Все платные фазы выполняются только с
`--yes` при явном согласии владельца на траты (грант 10 000 ₽). Без `--yes`
все скрипты — сухой прогон, денег не тратят.

Два пути, выбирайте один:

- **Путь A — «большая кнопка»**: одна команда, всё подряд, ≈ **1 925 ₽**
  (остаток гранта после прогона ≈ 6 100 ₽). Так и задумано: код сам проверяет
  и пишет, человек ничего не дописывает руками.
- **Путь B — мастер-промпт вручную**: вставить текст в AI Studio → чат с
  **Alice AI LLM Flash** и дать модели файлы. Так видите весь процесс глазами,
  но 48 вебинаров и 121 сцена вручную — долго. Нужно, только если хочется
  контролировать каждую строку.

## Путь A. Одна команда

```bash
cd ~/gib          # путь к репозиторию на вашем маке
YANDEX_API_KEY=<ваш ключ AI Studio> npx tsx scripts/yandex-full-package.ts --yes
```

Что делает по порядку (всё идемпотентно, повторный запуск пропускает сделанное):

| # | Фаза | Что происходит | Где промпт | Цена |
|---|------|----------------|------------|------|
| 1 | parent-webinars | 12 родительских вебинаров из кода программы (0 ₽, локально) | `scripts/gen-parent-webinars.ts` | 0 ₽ |
| 2 | webinar-check | LLM читает все 48 вебинаров: выдуманные факты/цифры, небезопасность, тон, соответствие неделе, длительность; вердикт `ok\|fix\|block` + список проверяемых утверждений → `out/webinar-check.csv` | `scripts/yandex-webinar-check.ts` | ≈150 ₽ |
| 3 | storyboards | LLM раскадровывает каждую из 121 уникальной сцены × 3 линейки: 6–8 кадров, план/ракурс/действие/реплика (дословно из ink)/эмоция/секунды/камера → `data/storyboards.json` + `out/storyboards/<scene>.md` | `scripts/yandex-storyboard.ts` | ≈102 ₽ |
| 4 | expand-webinars | LLM добирает учительские вебинары до 25–30 мин голоса alena, не переписывая готовое | `scripts/expand-webinars.ts` | ≈125 ₽ |
| 5 | art-stage | LLM разворачивает каждую из 121 сцены в постановку (локация из канона, действие глаголом, эмоция, до 3 предметов) → `data/art-shotlist.json`. **Без этой фазы все кадры рисуются по одной оффлайн-эвристике («комната, спокойный, добрый») и выходят одинаковыми.** Уже сгенерированные записи сохраняются | `scripts/art-stage.ts` | ≈25 ₽ |
| 6 | catalog | Сборка переиспользуемых кадров: hero+локация+эмоция → `data/frame-catalog.json` (0 ₽, оффлайн). Принцип владельца: один кадр вставляется во все сцены с той же постановкой — см. docs/frame-reuse.md | `scripts/build-frame-catalog.ts` | 0 ₽ |
| 7 | art | Alice AI ART **по каталогу** (не по сценам): ~24–120 кадров × `--candidates=2` вместо 726 → `out/art/frames/`; уже готовые пропускаются; `--band=8-10` — только одна линейка | `scripts/yandex-art-frames.ts` | ≈60–270 ₽ (при 24 кадрах ≈107 ₽) |
| 8 | stills | Разложить отобранные/сгенерированные кадры по `out/cinema/_stills/<scene>-<band>.png` (копии, дублируются из каталога) | `scripts/link-frame-stills.ts` | 0 ₽ |
| 9 | cinema | Ken Burns + войс из **отобранных вами** кадров `out/cinema/_stills/` → `out/cinema/` | `scripts/render-cinema.ts` | 0 ₽ |
| 10 | cinema-manifest | Сборка `public/cinema/manifest.json` | `scripts/build-cinema-manifest.ts` | 0 ₽ |
| 11 | tests | `test:content` + `test:cinema-manifest` + `tsc --noEmit` | пакет | 0 ₽ |

Фаза 9 сама пропустится, пока в `out/cinema/_stills/` нет кадров — сначала
ваш отбор глазами из `out/art/` (ошибка/каша → `out/art-rejects/`).

Полезные флаги:

```bash
# сухой прогон (план и деньги, ничего не тратится) — без ключа:
npx tsx scripts/yandex-full-package.ts

# только проверки, без трат:
YANDEX_API_KEY=... npx tsx scripts/yandex-full-package.ts --yes --only=tests

# пропустить дорогую арт-фазу (только тексты и раскадровки, ≈400 ₽):
YANDEX_API_KEY=... npx tsx scripts/yandex-full-package.ts --yes --skip=art

# арт только под одну возрастную линейку (герои одной линейки + все B-roll):
YANDEX_API_KEY=... npx tsx scripts/yandex-full-package.ts --yes --band=8-10

# пилот недели 1 вместо всей программы:
YANDEX_API_KEY=... npx tsx scripts/yandex-full-package.ts --yes --only=art --only=art-stage

# ПОЛНОЦЕННЫЙ ПЕРЕПРОГОН «полноценно всё» — раскадровки и добор с исправленными промптами:
# ≈600–700 ₽ заново (проверка 150 + раскадровки 102 + добор 75–200). Арт НЕ
# перегенерируется: готовые кадры пропускаются. Старые .full.md будут заменены.
YANDEX_API_KEY=... npx tsx scripts/yandex-full-package.ts --yes --force

# отдельная фаза:
YANDEX_API_KEY=... npx tsx scripts/yandex-storyboard.ts --yes
YANDEX_API_KEY=... npx tsx scripts/yandex-webinar-check.ts --yes
```

Итог расхода дописывается в `out/ai-grant-spend.jsonl` — цифры для грантового
кейса берутся оттуда, не из головы.

## Путь B. Мастер-промпт (полный текст для вставки)

Откройте AI Studio → **Чат** → модель **Alice AI LLM Flash** → вставьте
блок ниже целиком первым сообщением. Дальше прикладывайте файлы по этапам
(этап 1 — вебинары партиями по 6–8 файлов; этап 2 — по одной сцене на
сообщение; этап 5 — по одной неделе на сообщение).

```
Ты — строгий редактор-методист программы «Гиб».

Контекст (не выдумывай сверх этого):
• «Гиб» — тренажёр мягких и когнитивных навыков для детей 5–13 лет,
  Telegram Mini App. 12 недель × 5 дней = 60 дней; каждый день = 1 история
  мягкого навыка + когнитивные задания; три возрастные линейки: 5–7, 8–10,
  11–13 (у каждой — свой текст истории, вариантов решений три: good/partial/
  bad). Всего 180 вариантов.
• Мягкие компетенции: самопознание, саморегуляция, эмпатия, навыки
  отношений, ответственные решения, мышление роста, творческое мышление.
• Когнитивные навыки: внимание, торможение, гибкость, рабочая память,
  логика, планирование.
• Программа: неделя держит самую частую компетенцию среди своих пяти дней
  (см. docs/program.md; проверка npm run test:competency-alignment).
• Дословные фразы кода и ink — святыня: копируй их символ в символ.
  Никогда не «улучшай» реплику ребёнка или кода.
• Русский язык. К взрослым — на «вы». Детские тексты читаемы целевой
  линейкой (5–7 — короткие простые фразы; 11–13 — подростковый регистр).

Жёсткие правила:
1. Не выдумывай факты, цифры, исследования, названия методик, имена
   специалистов. Не знаешь — пиши «НЕТ ДАННЫХ», это корректный ответ.
2. Безопасность: никакого стыда/оценки личности ребёнка («ты плохой/
   ленивый/слабый»). Sensitive-темы (смерть, насилие, буллинг,
   самоповреждение, зависимости): единственно допустимый совет — показать
   взрослому и обратиться к психологу; никаких самостоятельных «советов».
3. CTA в конце текста — ровно один.
4. Не переписывай то, что работает; правки — точечные и объяснённые.
5. Формат ответа строго по этапу; никакого «от себя» вне формата.
6. Заметил проблему вне своего этапа — не чини молча, а вынеси в раздел
   «ВНЕ ЭТАПА» в конце ответа.

Этап 1 — Вебинары (teacher: 36 базы + 2 сверх программы, content/webinars/teacher/NN-*.md;
parent: 12 файлов content/webinars/parent/NN-*.md). Для каждого:
а) факты: каждая цифра/исследование/процент/источник — либо проверяемо,
   либо выдумано → «ДЕРЖИТСЯ НА ФАКТЕ: <список>» или «ВЫДУМАНО: <что>»;
б) безопасность: sensitive → только «к психологу/взрослому», один CTA,
   нет оценок личности, нет обещаний «вылечит/избавит»;
в) тон: тёплый, без панибратства и канцелярита, «вы»;
г) сверка с программой: неделя файла = неделям его дней в коде; компетенция
   недели = самой частой в днях (иначе файл вводит родителя в заблуждение);
д) длительность: посчитай слова, из слов — минуты голоса alena
   (≈140 слов/мин для русской речи) и сравни с «≈ N минут» в шапке;
   расхождение > 20 % — исправь шапку или допиши содержание;
е) вердикт на файл: ok | fix | block. Для fix — точечная диагностика
   (файл:строка — что не так — как чинить), НЕ переписывание целиком.
   Для block — что недопустимо и почему.
Формат этапа 1: таблица | файл | вердикт | факты | безопасность | тон |
сверка с программой | слова | минуты (шапка/факт) | фиксы |
+ раздел «ВНЕ ЭТАПА».

Этап 2 — Раскадровки (одна сцена = один ink-файл; ревизии-линейки отдельно).
Для каждой сцены 6–8 кадров; каждый кадр:
| n | план (общий/средний/крупный/деталь) | ракурс | действие в кадре |
реплика (ТОЛЬКО дословная из ink; нет реплики → «—») | эмоция героя |
секунды (вся сцена ≈ 20–26 с) | камера (статика / наезд 5–10 % / панорама) |
Плюс: если файл относится к линейке 5–7 — замедленный темп, мягкие
переходы; 11–13 — больше пауз и крупных планов. needs_review=true, если
реплику не удалось вынуть дословно или сцена неоднозначна.
Формат этапа 2: JSON {"scene": "...", "band": "...", "frames": [...],
"needs_review": bool} — ничего вне JSON.

Этап 3 — Добор учительских вебинаров до 25–30 мин голоса alena.
Цель — не «больше текста», а закрытие пропусков: крючок в первые 30 с,
3–4 смысловые точки, разбор частых ошибок учителя по дням недели, один
CTA в конце. Запрещено: водянистые повторы, новые цифры «от себя», смена
уже вычитанных формулировок. Помечай добавленное маркером <!-- ДОБАВЛЕНО -->
и в конце — сводку «что добавил и почему».

Этап 4 — Проверка корпуса ink (файлы НЕ изменяются). Для каждой истории:
сложность чтения линейки (5–7: ≤ 9 слов в фразе, без причастных оборотов;
8–10: ≤ 13; 11–13: подростковый синтаксис), теги навыков vs. реальное
содержание (ошибка тега — отдельная строка), risk-сцены: любая сцена с
дракой, угрозой, самоповреждением, темой смерти/насилия/буллинга →
флаг RISK + что именно; конец ветки (good/partial/bad) vs. заявленная
компетенция недели.
Формат этапа 4: таблица | файл | сложность vs линейка | тег vs содержание |
RISK | расхождение ветки и компетенции | —
+ раздел «ВНЕ ЭТАПА».

Этап 5 — Сквозная сверка «всё логически сходится». Возьми пачками по неделе:
недели ↔ компетенции (самая частая в днях), дни ↔ practiceTaskId (задание
существует и навык совпадает), вебинары ↔ программа (темы недель, цели,
вопросы за ужином совпадают с кодом), раскадровки ↔ ink (реплики дословные),
parent-вебинары ↔ недельные отчёты. Выход — таблица | объект | что не
сходится | тяжесть: косметика\|смысл\|блокер | как чинить.

Финал (после всех этапов): один абзац «О чём заявке на следующий грант
стоило бы рассказать» — только из того, что ты реально увидел в материалах.
Никакого маркетинга сверх фактов.
```

Команды вызова (те же фазы, но глазами — те же в файлах):

```bash
npx tsx scripts/yandex-webinar-check.ts        # сухой расчёт
YANDEX_API_KEY=... npx tsx scripts/yandex-webinar-check.ts --yes
YANDEX_API_KEY=... npx tsx scripts/yandex-storyboard.ts --yes [--only=w3d2] [--limit=20]
YANDEX_API_KEY=... npx tsx scripts/expand-webinars.ts --yes
YANDEX_API_KEY=... npx tsx scripts/yandex-art.ts --only=w1 --candidates=4 --yes   # сначала w1 (пилот)
```

## Что LLM сделать НЕ может (и кто делает)

| Шаг | Кто |
|---|---|
| Отбор годных кадров из `out/art/` в `out/cinema/_stills/` | вы, глазами |
| Вычитка вебинаров перед озвучкой alena (`.full.md`) | вы + методист |
| `yandex-webinar-check`, `yandex-content-review` — вердикты ok | это **вторые глаза**, не одобрение к публикации |
| Пилот «неделя 1» артом до всей программы | вы (решение) |
| Мерж в `main` («сливай») | вы |
| Google Drive | выключен; включение — только ваше |

## Честные ограничения

- LLM не имеет доступа в сеть: вечнозелёные факты она знает, а ваши файлы —
  только те, что даны в контексте. Вне контекста она выдумывает → правило
  «НЕТ ДАННЫХ» в мастер-промпте.
- Вебинары родителей (12 файлов, `content/webinars/parent/`) созданы
  шаблоном из кода (не LLM). Их судьба не утверждена вами: ранее звучало,
  что родительский вебинар отменён. Скажите «удали родительские» — вычищу;
  скажите «оставь» — останутся в ветке до вычитки.
- `expand-webinars` и добор внутри этапа 3 не перезаписывают готовое:
  добавления идут под маркером, оригинал цел.
- Итоги трат смотрятся в `out/ai-grant-spend.jsonl`; любые числа «сколько
  потрачено» в документах для гранта — оттуда.
