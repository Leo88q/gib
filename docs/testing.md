# Как устроены проверки

03.11.2026 · числа пересчитаны скриптом, а не на глаз: 240 файлов тестов,
3264 проверки. Команда одна — `npm test`.

Этот документ для того, кто придёт в репозиторий после нас. Он отвечает на три
вопроса: почему проверок так много, что именно они ловят и почему некоторые
из них — про текст, а не про код.

---

## 1. Почему проверок больше, чем кажется нужным

3264 проверки на приложение, в котором 36 занятий и 60 историй, — это много.
Причина не в педантичности, а в характере продукта: он работает с детьми, и
почти каждая ошибка здесь не падает, а **тихо говорит неправду**. Родитель
видит отчёт, в котором оценка спрятана в формулировке. Педагог читает разбор
занятия, на котором не будет описанного упражнения. Школа получает
формулировку ФГОС, не совпадающую с рабочей программой.

Ошибки такого рода не видно ни в тестах типов, ни в сборке, ни на экране — их
видно только тому, кто специально ищет. Поэтому половина проверок — про слова.

## 2. Четыре вида проверок

| Вид | Что проверяет | Пример |
|---|---|---|
| **Поведение** | маршрут отвечает, права не текут, данные сохраняются | `test-lessons-route`: чужой профиль — 404, а не 403 |
| **Содержание** | в текстах нет обещаний, оценок, медицины | `test-year-stage`: «терапия», «коррекция», «диагноз» не встречаются |
| **Согласованность** | числа в документах совпадают с кодом | `test-research-docs`: 54 навыка, 139 историй, 39 из 54 в конструктах |
| **Контракт** | экран и маршрут не разойдутся молча | `test-teacher-route` + `test-teacher-cabinet-ui`: подложка с двух сторон |

Последний вид появился позже остальных и оказался самым нужным. Маршрут отдавал
шесть полей методической подложки, экран читал их же — и оба теста были
зелёными, даже если одна сторона исчезнет. Теперь маршрут обязан отдать все
шесть с числами, а экран — прочитать все шесть.

## 3. Проверки, которые ловят не код, а прозу о коде

Самая частая поломка в этом репозитории — не сломанный код, а **документ,
который перестал быть правдой**. Каталог навыков вырос с 48 до 54, истории —
до 139, покрытие пересчиталось. Код при этом был в порядке. А документы,
которые читает научный руководитель, продолжали говорить «31 навык из 48».

Поэтому есть тесты, которые читают `.md` и сверяют с данными:

- `test-research-docs` — 54 навыка, 139 историй, 39 из 54, таблица по 12
  неделям, 50 из 60 дней, отсутствие медицинских формулировок;
- `test-university-doc` — числа года (36 занятий, 60 дней, 12 показов);
- `test-product-organism` — реестр недоделок: 32 пункта, без повторов.

Проверка «документ называет число» слабая: она не видит, что число устарело.
Сильная — «документ называет число, которое я только что посчитал из кода».
Везде, где это возможно, используется вторая. Проверено подменой: правка одной
клетки таблицы по неделям роняет `test-research-docs`.

## 4. Проверки, которых нет и не будет

Честный список — чтобы не думать, что 3264 проверки закрывают всё.

| Чего нет | Почему | Чем закрывается |
|---|---|---|
| **Реальные устройства** | Telegram и MAX, Android и iOS не эмулируются в CI | P0, пункт 4 реестра: проверка руками |
| **Экспертиза содержания** | тест видит слова, но не видит, годится ли сцена для 8 лет | P0, пункт 3: независимый эксперт |
| **Работа педагога** | удержит ли план встречи живую группу | пилот, наблюдение |
| **Эффект на ребёнка** | продукт не измеряет результат | `docs/research-passport.md`, уровни 2–3 |
| **Внешний вид** | вёрстка проверяется по классам, а не по пикселям | `test-method-ui-styles` ловит класс без правила, но не уродливую вёрстку |

Про последнее важно: тест на стили появился после того, как выяснилось, что у
кабинета педагога **не было ни одного правила в CSS** — планы и ученики
выводились простым текстом, и никто этого не видел, потому что на экран не
смотрели. Класс без правила не ловит ни TypeScript, ни сборка. Теперь ловит
тест. Но «стиль есть» не значит «экран хороший»: это по-прежнему смотрит
человек.

## 5. Как добавить проверку

1. Файл `scripts/test-<что>.ts`, запуск через `tsx`, без top-level await:
   обёртка `async function main()` (скрипты собираются как cjs).
2. В `package.json` — скрипт `test-<что>` и добавление в цепочку `npm test`.
3. Если тест трогает хранилище — свой `GIB_DATA_FILE` в `/tmp`: рабочую базу
   тест не должен даже открывать.
4. Если в тесте новое число, которое называет документ, — правится и документ,
   и число в `test-university-doc` (он считает файлы тестов, включая себя).
5. Формулировки проверяются конструкциями, а не корнями слов. «Создаёт
   обязанность ответить» — это объяснение вреда, а не давление на ребёнка;
   «рефлексия» — и направление ФГОС, и рефлексия ребёнка. Обе эти проверки
   сначала падали на правильном тексте, и правился тест, а не текст.

## Приложение: что запускать точечно

```bash
npm test                        # всё
npm run test-year-stage         # лестница выхода и приёмы
npm run test-year-method-materials  # ФГОС, страницы, видео, запас
npm run test-year-briefs        # 36 разборов
npm run test-year-showcases     # 12 показов как целое
npm run test-method-ui-styles   # классы в JSX против globals.css
npm run test-research-docs      # числа исследования против кода
npm run map:research            # пересчёт покрытия конструктов
```
