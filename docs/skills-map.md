# Карта гибких навыков

Учебная часть строится вокруг **48 гибких навыков** внутри семи компетенций.
Карта отвечает на два вопроса: где навык отрабатывается и не остался ли он
заявленным, но пустым.

## Структура

| Файл | Что содержит |
|---|---|
| `lib/content/skills-catalog.ts` | 48 навыков: `id`, `competency`, `title` для взрослого, `child` для трёх возрастов, `looksLike` |
| `lib/content/story-skills.ts` | карта «история → навыки»: какие умения тренирует каждая сцена |
| `lib/content/skill-gap-stories.ts` | шесть историй под навыки, у которых не было ни одной сцены |
| `lib/content/program/skill-gap-practices.ts` | практика поддержки для этих шести историй |
| `scripts/test-skills-catalog.ts` | проверка: 48 навыков, 127 историй, полное покрытие |
| `scripts/skills-map.ts` | карта в терминале |
| `scripts/test-competency-alignment.ts` | проверка: компетенция истории совпадает с её навыками |

Распределение: самопознание 7, саморегуляция 8, эмпатия 7, отношения 8,
ответственные решения 8, творческое мышление 5, мышление роста 5.

## Зачем карта руками, а не по ключевым словам

Автоматическая разметка по словам ошибается в обе стороны: «замолчал» похоже
на «молчи», а история про поделку выглядит как история про внимание. Каждая
связь прочитана по тексту вопроса и вариантов: история относится к навыку,
только если ребёнок действительно тренирует его, выбирая ответ.

Одна история может тренировать несколько навыков: «предложить помощь» и
«уважать отказ» часто живут в одной сцене.

## Что было найдено

До этой работы 121 история покрывала 42 навыка из 48. Шесть не встречались ни
разу: `name_feelings`, `recognize_strengths`, `hold_impulse`, `comfort_other`,
`not_judge`, `combine_ideas`. Для них написаны шесть историй с практикой и
карточкой в дне программы — иначе история остаётся на складе и до ребёнка не
доходит.

## Компетенции историй

Компетенция истории управляет тремя вещами: на какой квест её ставит движок,
в какую тему карты она попадает у ребёнка и что увидит родитель в отчёте.
Если история про поддержку друга помечена как «самопознание», ребёнок видит
её не в той теме, а родитель — не тот прогресс. Ошибка не падает: всё
работает и врёт.

Поэтому проверка опирается на карту навыков: навык всегда принадлежит ровно
одной компетенции. Если все навыки истории принадлежат одной компетенции, а
сама история помечена другой — это расхождение, и `test:competency-alignment`
падает.

Когда такая проверка появилась, нашлось 14 расхождений. Причина оказалась
системной: недели 7–10 — когнитивные («Внимание», «Память», «Гибкость»,
«План»), и их истории размечены «ближайшей социальной» компетенцией. Дни 8
про списки и подготовку были помечены как «Самопознание», а неделя 9
«Гибкость» целиком относилась к «Навыкам отношений».

После разбора расхождений не осталось: истории перенесены в те компетенции,
о которых они на самом деле.

## Компетенция карточки и компетенция дня

Ребёнок выбирает одну историю из двух, а не проходит обе. Значит, тема дня —
та, которую он выбрал, и карточка вправе относиться к другой компетенции.
Раньше движок это запрещал (`story_competency_mismatch`), и запрет заставлял
либо метить историю чужой компетенцией, либо оставлять день без второй
карточки. Запрет снят; проверяется другое — что выбор есть у каждого из 60
дней.

## Команды

```bash
npm run skills:map              # покрытие по компетенциям, навыки без сцен
npm run skills:map -- empathy   # детализация по одной компетенции
SKILLS_VERBOSE=1 npm run skills:map   # какие навыки тренирует каждая история
npm run test:skills-catalog     # проверка покрытия (входит в npm test)
npm run test:competency-alignment  # компетенции историй и выбор дня
```

## Что видит ребёнок

Вкладка «Карта» — два уровня.

**Первый — темы.** Семь компетенций как темы занятий: «Историй завершено»,
«практик поддержки». Это факты, а не оценка.

**Второй — умения.** Те же 48 навыков, но своими словами и по возрасту:
«Понять, что я сейчас чувствую», а не «Называть чувства словами». Ребёнок
открывает тему и видит список.

Правила этого уровня (`lib/engine/skill-map.ts`):

- **Встреча, а не уровень.** Умение либо встречалось в пройденной истории,
  либо нет. Полей `score`, `level`, `percent` в ответе API нет — их отсутствие
  проверяет `test:skill-map`.
- **Непройденное видно.** Пустая ячейка честнее галочки: карта не должна
  превращаться в список достижений.
- **Повтор не накручивает.** Та же история второй раз не делает умение «более
  освоенным»; две разные истории считаются.
- **Без похвалы и без «ты отстаёшь».** Фраза о состоянии говорит, сколько
  умений встретилось, и добавляет, что пропусков здесь нет.
- **Названия тем — не из методички.** «Справляться с собой», а не
  «Саморегуляция»: второе — слово из отчёта взрослого.

Проверки: `test:skill-map` (движок), `test:skill-map-ui` (интерфейс).

## Достижимость, а не только покрытие

Покрытие контентом ещё не значит, что ребёнок до навыка дойдёт. В выдаче дня
максимум три карточки, а за один проход программы выбирается одна история в
день. Поэтому `test:skills-catalog` проверяет не только «навык есть в
контенте», но и «навык достижим за один проход».

Так нашлась ошибка, которую не видно по карте: две новые истории стояли
третьими в дне, и за один проход 2 навыка оставались недостижимыми. После
переноса — 48 из 48.

## В отчёте родителю

Блок «Гибкие навыки на этой неделе» перечисляет навыки из историй недели,
сгруппированные по компетенциям. Это список тем, а не оценка ребёнка: навык
либо встречался в сюжете, либо нет. Ни цифр, ни рейтингов, ни сравнения с
другими детьми.

## Правила формулировок

Тест `test:skills-catalog` проверяет, что формулировки:

- не оценивают ребёнка («молодец», «ты должен», «стыдно»);
- не обещают результат («гарантированно получится», «избавит»);
- различаются по возрастам хотя бы на две формулировки из трёх;
- короче 60 знаков для детской фразы.

Формулировки для трёх возрастов — не украшение. Одна и та же фраза для 6 и 12
лет означает, что возрастной адаптации нет.
