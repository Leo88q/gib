# Что рисуем для уроков и интерфейса

Продолжение к `README.md`: там решён **каст** (3 проводника, 6 существ навыков, питомец),
здесь — **вещи и карточки**, то есть то, из чего собираются сами экраны.

## Правило разделения

| Слой | Чем делается | Почему |
|---|---|---|
| Рамка карточки, сетка, состояния, прогресс | **код** (CSS + токены) | текст должен оставаться текстом: его читают скринридером и переводят |
| Содержимое карточки: предмет, существо, сцена | **арт** (PNG) | то, что нельзя собрать из типографики |
| Аватары ребёнка, иконки навыков в мелком размере | **SVG** (`components/avatarParts.tsx`) | перекрашиваются токенами, не требуют ретины |

Отсюда следует: «карточка предмета» — это **CSS-рамка + одна картинка предмета**, а не
нарисованная карточка целиком. Рисовать карточку картинкой значит потерять доступность,
адаптив и возможность поменять цену без перерисовки.

## 1. Предметы урока (то, что ребёнок трогает в упражнении)

Пять типов заданий в коде (`components/BlockPuzzle`, `BubbleGame`, `Shape`,
`SwitchRounds`, `LogicBoard`) сейчас рисуются фигурами и текстом. Для них нужны ровно
предметы, а не иллюстрации:

| id | Предмет | Где |
|---|---|---|
| `block` | деревянный блок | `BlockPuzzle` |
| `bubble` | мыльный пузырь с радужным блеском | `BubbleGame` |
| `shapes` | куб, шар, конус — набор | `Shape` |
| `cards` | пара карточек «рубашкой вверх» | `SwitchRounds` |
| `hourglass` | песочные часы с янтарным песком | таймер, пауза, торможение |
| `notebook` | раскрытый блокнот с чек-листом | планирование, рюкзак |

## 2. Предметы гардероба (15 позиций из `lib/gamification.ts`)

Сейчас все 15 предметов — SVG-варианты поверх аватара. Их видно только на персонаже,
поэтому в магазине карточка предмета показывает **текст и цену без картинки**. Это
главная дыра интерфейса, которую закрывает этот лист.

Носимое (9): кепка, бандана, очки, наушники, корона, шарф, рюкзак, суперкостюм, жилет.
В комнату (4): ковёр, лампа, плакат, растение.
Питомцы (2 из магазина) **не рисуются**: по решению о касте личный питомец один,
а `pet_cat` / `pet_dragon` — остаток старой системы, они уходят вместе со старым артом.

## 3. Карточки интерфейса (четыре типа, все на CSS)

| Карточка | Что внутри | Где |
|---|---|---|
| Карточка дня | существо навыка, тема, «2 мин», чип возраста | игровой экран |
| Карточка выбора | текст варианта + строка-пояснение, все равны по весу | `ScenarioView` |
| Карточка предмета | картинка предмета, название, цена, «надето» | магазин, гардероб |
| Карточка места | иллюстрация одного из 7 мест района, 1–2 практики | карта навыков |

## 4. Контракт файлов

```
public/art/v2/items/<id>.png     600×600, прозрачный фон, предмет по центру, поля 8 %
public/art/v2/places/<id>.png   1600×900, сцена, безопасная зона под текст по центру
public/art/v2/creatures/<id>.png 900×1200, персонаж в полный рост на прозрачном
```

Правила, чтобы партия не рассыпалась (из ошибок первого захода с существами):

1. **один свет** — сверху-слева, мягкий, без цветных отражений;
2. **один фон при отрисовке** — тёплая бумага `#FDF4E9`, вырезаем уже потом;
3. **один масштаб** — предмет занимает 80 % кадра, независимо от реального размера;
4. **без текста в картинке** — надписи, цены и подписи ставит код;
5. **один светящийся элемент** на предмет, если он вообще нужен: янтарь `#F2B544`.

## 5. Что осталось за границей этого листа

- **Сценный арт под 60 историй** — самая дорогая часть и самая спорная: 60 картинок
  устаревают быстрее, чем тексты. Пока истории показываются текстом, существом навыка
  и местом района. Если рисовать — то 7 мест, а не 60 сцен.
- **Анимации** (питомец дышит, существо мигает) — после паспорта стиля, отдельным
  листом спрайтов, не гифками.
